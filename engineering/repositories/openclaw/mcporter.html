Upstream contribution · openclaw/mcporter

mcporter · Passing explicit empty values through the MCPorter CLI

Rudy Celekli’s engineering portfolio · AI-assisted summary

Problem

The CLI discarded empty positional strings after the literal separator. A caller sending an explicit empty text value to an MCP tool therefore sent an absent argument, which the server schema rejected.

Engineering response

The upstream consolidation incorporates the fix from PR #412, preserving argument positions after the literal separator, including empty strings and flag-like values intended as tool input.

Evidence and scope

The original PR records a real CLI subprocess and local SDK echo server. The baseline rejects the missing string, while the patched request returns an empty text item. The credited upstream consolidation reports 2,128 passing tests and exact-head cross-platform CI.
