Upstream contribution · openclaw/goplaces

goplaces · Keeping proxy queries and request paths distinct in goplaces

Rudy Celekli’s engineering portfolio · AI-assisted summary

Problem

Appending a Places endpoint suffix to the raw base URL could put the operation into a proxy query parameter. An override such as /v1/?tenant=one acquired a modified tenant value instead of dispatching to the intended Places operation.

Engineering response

The upstream consolidation integrates the URL fix from PR #74. It joins parsed path components while retaining escaped path segments and existing proxy queries, and distinguishes a Routes base prefix from an already complete computeRoutes endpoint.

Evidence and scope

The original reproduction records loopback HTTP requests from the actual CLI and public Go consumers, plus Go build and race checks. The upstream diff includes an endpoint-query regression and credits the original reports. The loopback fixture uses a dummy credential.
