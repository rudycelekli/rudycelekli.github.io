Upstream contribution · vectorize-io/hindsight

hindsight · Keeping HTTP status visible in Hindsight CLI errors

Rudy Celekli’s engineering portfolio · AI-assisted summary

Problem

Diagnostic words in a server response body could override the real HTTP status shown to an operator. For example, a 403 whose body mentioned a timeout could appear to be a transport failure.

Engineering response

The classifier now uses the HTTP failure heading while the formatter keeps the complete response detail. Genuine transport errors continue through their existing classification.

Evidence and scope

Two formatter regressions reproduced status misclassification in the existing error module. The contribution reports passing cases for both and separate controls for transport errors. The fixtures exercise formatter behavior offline.
