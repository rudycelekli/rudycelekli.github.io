Upstream contribution · earthtojake/text-to-cad

text-to-cad · Preserving native CAD worker failure reasons in the Viewer

Rudy Celekli’s engineering portfolio · AI-assisted summary

Problem

When a CAD daemon worker crashed or was killed, the Viewer could report a failed update without the diagnostic the process had already provided. This left both native crashes and intentional cancellation hard to distinguish at the job boundary.

Engineering response

The daemon now records a worker's exit code or terminating signal as the job's failure reason. The maintainer rebased the contributor patch and integrated it alongside existing telemetry.

Evidence and scope

The maintainer's upstream commit explicitly credits the original PR and contains a daemon-client regression. A separate credited commit preserves daemon-channel descriptor ownership during cancellation. These changes concern recorded job state and transport ownership.
