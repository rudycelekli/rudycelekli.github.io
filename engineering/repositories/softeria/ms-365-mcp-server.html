ms-365-mcp-server · Enforcing tool boundaries and signing mail according to its schema

Rudy Celekli’s engineering portfolio · AI-assisted summary

Problem

A Microsoft 365 MCP client could receive account-management tools under restrictive stdio settings. Separately, generated mail schemas used PascalCase body keys while the signing path read lowercase keys, causing signed sends to fail and some replies to miss the configured signature.

Engineering response

The stdio registration now applies tool-name and read-only filters and skips MSAL account tools under an environment-token session. The signing helper accepts both supported key spellings and writes back through the spelling the caller used. A third change avoids quadratic email-redaction matching on long attachment text.

Evidence and scope

The PRs report focused filter, signature, and redaction checks. The signature suite went from two failing regressions to 38 passing tests, and the performance report includes a size-doubling baseline for redaction. The mail tests exercise request construction without live Microsoft Graph delivery.
