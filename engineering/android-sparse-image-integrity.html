Preserve payload bytes and checksums in Android sparse images

A merged Ghidra contribution correcting FILL byte order and skipped-block output and CRC accounting.

Upstream: NationalSecurityAgency/ghidra · PR #9805 · Author: rudycelekli

The problem

Ghidra’s Android sparse-image decompressor reconstructed raw payloads from chunk records. Its FILL path reversed the stored four-byte pattern. Its DONT_CARE path wrote zero-filled output without including those bytes in CRC accounting, and a skipped region exactly equal to the 1 MiB buffer produced no output.

A boundary example

For a skipped region of exactly 1,048,576 bytes, the old greater-than-buffer branch was not entered and the remainder was zero. The resulting write therefore had zero length. The corrected loop emits the full region in bounded writes and updates the CRC for each emitted byte. This example follows from source inspection; it is not a fresh execution result.

The accepted change

The merged source creates a zero buffer bounded by the smaller of the region length and output-buffer size, then writes until the region is exhausted. Each iteration checks cancellation and updates both the checksum and output. The FILL path reconstructs the byte pattern in the order used by the little-endian reader.

Engineering lesson

For binary transformations, byte order, output length and checksum accounting are one contract. Skipped regions still contribute bytes to the reconstructed image, and exact buffer boundaries deserve explicit attention.
